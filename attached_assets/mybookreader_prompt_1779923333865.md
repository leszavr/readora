# Промпт на имплементацию Readora с нуля

Ты должен написать новое приложение **Readora** с нуля. Это не рефакторинг и не вырезание функциональности из VoxLibris. Старый проект используется **только как технический референс**.

## Ключевое условие по референсу

В качестве референса технических решений используй каталог:

```text
./tmp/voxlibris
```

Пользователь скопирует туда код VoxLibris. Используй этот каталог только для изучения подходов:

- парсинг FB2/EPUB;
- хранение книг;
- структура ридера;
- сохранение прогресса чтения;
- настройки ридера;
- авторизация;
- административная панель;
- docker/deployment;
- работа с PostgreSQL/MinIO, если в новом проекте они будут выбраны.

Не копируй старую архитектуру бездумно. Readora — новое приложение с чистой структурой, меньшим объемом и только нужной функциональностью.

---

# 1. Цель проекта

Нужно реализовать веб-приложение **Readora** — персональную библиотеку и ридер для чтения загруженных пользователем книг.

Основные части приложения:

1. Главная страница.
2. Авторизация и роли.
3. Персональная библиотека пользователя.
4. Загрузка и парсинг книг FB2/EPUB.
5. Ридер с настройками и оглавлением.
6. Административная панель.
7. Хранение данных, файлов и метаданных.
8. Безопасные миграции и воспроизводимый запуск.

---

# 2. Общие требования

## 2.1. Качество реализации

Сделай приложение простым, надежным и расширяемым. Не добавляй социальные функции, клубы, лайвы, чаты, геймификацию и любые функции, которых нет в задании.

## 2.2. Минимальный обязательный продукт

MVP должен включать:

- регистрацию/вход;
- роли `user`, `moderator`, `admin`;
- главную страницу;
- персональную библиотеку;
- одиночную и пакетную загрузку книг;
- парсинг FB2/EPUB;
- карточки и список книг;
- поиск, фильтрацию, сортировку, группировку;
- чтение книги в ридере;
- сохранение прогресса;
- настройки отображения текста;
- оглавление;
- административную панель;
- миграции БД;
- базовую защиту приложения.

# 3. Главная страница

## 3.1. Шапка

В шапке должны быть:

- логотип Readora;
- справа зона пользователя.

### Для авторизованного пользователя

Показывать аватар с выпадающим персональным меню.

### Для неавторизованного пользователя

Показывать действия:

- Вход;
- Регистрация.

## 3.2. Персональное меню

В меню авторизованного пользователя должны быть пункты:

- Моя библиотека;
- Административная панель — только для пользователей с ролью `admin` или `moderator`;
- Выход.

## 3.3. Hero

Hero-блок должен объяснять ценность приложения: загрузить книгу, настроить комфортное чтение и продолжить с нужного места.

Обязательная кнопка:

- **Читать**.

Поведение кнопки:

- если пользователь авторизован — переход в персональную библиотеку;
- если пользователь не авторизован — показать вход/регистрацию или перейти на страницу входа с понятным CTA для регистрации.

## 3.4. Блок «Популярные книги»

Нужно динамически выводить карточки книг из топа наиболее читаемых книг на сайте.

Карточка должна показывать:

- обложку;
- автора;
- краткое описание.

Ограничения:

- карточка не должна открывать книгу;
- карточка не должна вести в ридер;
- карточка используется только как визуальная витрина;
- если данных нет, показывать аккуратное пустое состояние.

Источник топа:

- агрегировать по фактическому чтению/открытиям/прогрессу пользователей;
- для MVP допустимо считать популярность по количеству открытий книги или количеству пользователей, у которых есть прогресс по книге;
- не показывать приватные файлы так, чтобы другой пользователь мог получить доступ к книге. В публичном блоке допустимы только безопасные метаданные: обложка, автор, описание, название при необходимости.

## 3.5. Блок онбординга

Три шага:

1. Загрузи книгу.
2. Настрой ридер.
3. Читай.

## 3.6. Подвал

В подвале:

- логотип;
- слоган;
- копирайт.

# 4. Персональная библиотека

Персональная библиотека — основной рабочий раздел пользователя.

## 4.1. Что отображать

Показывать каталог книг, загруженных текущим пользователем.

## 4.2. Режимы отображения

Обязательные режимы:

- карточки;
- список.

Переключатель режима должен сохранять выбор пользователя локально или в настройках профиля.

## 4.3. Поиск и выборки

Нужно реализовать поиск и фильтрацию по:

- жанрам;
- автору;
- циклам;
- дате загрузки;
- дате последнего чтения.

## 4.4. Сортировка

Нужно поддержать сортировку минимум по:

- названию;
- автору;
- дате загрузки;
- дате последнего чтения;
- прогрессу чтения.

## 4.5. Группировка

Нужно поддержать группировку минимум по:

- автору;
- жанру;
- циклу;
- статусу чтения.

Статусы чтения для MVP:

- не начато;
- читается;
- прочитано.

## 4.6. Загрузка книг

Кнопка: **Загрузить**.

Поддержать:

- загрузку одной книги;
- пакетную загрузку нескольких книг;
- указание цикла при загрузке;
- автозаполнение метаданных из файла.

Форматы:

- FB2;
- EPUB.

## 4.7. Автоматический парсинг

При загрузке автоматически извлекать:

- название;
- автора;
- описание;
- обложку;
- жанры;
- язык, если доступен;
- год/дату публикации, если доступна;
- структуру книги;
- главы или другие элементы оглавления;
- теги форматирования, важные для отображения текста.

Если часть метаданных отсутствует, приложение должно позволить пользователю отредактировать их вручную.

## 4.8. Удаление книг

Нужно поддержать:

- удаление одной книги;
- выборочное удаление нескольких книг;
- удаление всех книг пользователя.

Удаление должно требовать подтверждения. Для опасных массовых действий нужна отдельная защита от случайного клика.

## 4.9. Безопасность библиотеки

Пользователь может видеть и читать только свои книги. Админ/модератор может управлять книгами через административную панель согласно ролям.

# 5. Ридер

Ридер — инструмент чтения загруженной книги.

## 5.1. Основное поведение

Ридер должен:

- открывать книгу из персональной библиотеки;
- отображать спарсенный текст;
- показывать текст поглавно, если главы определены;
- если главы не определены — делить текст на фрагменты до 1 авторского листа;
- лениво подгружать остальной контекст;
- сохранять прогресс чтения;
- восстанавливать позицию при повторном открытии.

## 5.2. Полноэкранный режим

Ридер должен иметь возможность разворачиваться в полноэкранный режим.

Требования:

- вход в полноэкранный режим;
- выход из полноэкранного режима;
- корректная работа настроек и оглавления в этом режиме;
- адаптивность для desktop и mobile.

## 5.3. Настройки ридера

Обязательные настройки:

- межстрочный интервал;
- размер шрифта;
- выбор шрифта;
- тема:
  - Светлая;
  - Темная;
  - Сепия;
- ширина текста / ширина полей;
- сброс настроек.

Настройки должны сохраняться для пользователя и применяться при следующем открытии ридера.

## 5.4. Оглавление

В ридере должно быть оглавление.

Оглавление должно показывать:

- список глав, если главы определены;
- другие структурные элементы, если они извлечены из книги;
- для книг без оглавления — список автоматически созданных фрагментов.

Клик по элементу оглавления должен переводить пользователя к соответствующей главе/фрагменту.

## 5.5. Прогресс

Сохранять:

- текущую главу/фрагмент;
- позицию внутри главы/фрагмента;
- общий процент прогресса;
- дату последнего чтения.

# 6. Административная панель

Доступ только для ролей:

- `admin`;
- `moderator` — с ограничениями, если нужны.

## 6.1. Панель управления

Основной dashboard должен показывать важную информацию:

- количество пользователей;

- количество активных читателей;

- последние загруженные книги;
- последние зарегистрированные пользователи;
- состояние системных настроек/сервисов, если доступно.

С dashboard должны быть переходы на подробные страницы управления.

## 6.2. Пользователи

Нужно поддержать:

- создание пользователя;
- редактирование пользователя;

- блокировку/разблокировку;
- установку ролей;
- пакетные действия;

- удаление книги;

- действия по одной книге.

Важно: админская работа с книгами не должна нарушать приватность пользовательских файлов. Если нужен просмотр, показывать метаданные и техническую информацию; доступ к содержимому книги должен быть явно ограничен и обоснован.

## 6.4. Жанры

Настройки должны храниться в БД или конфиге в зависимости от их природы. Секреты нельзя показывать в открытом виде.

# 8. Миграции

Так как приложение пишется с нуля, создай чистые миграции для новой схемы Readora.

Требования:

- миграции должны быть воспроизводимыми;
- миграции должны быть безопасными;
- использовать `IF NOT EXISTS`, где уместно;
- не завязываться на старую схему VoxLibris;
- не тащить лишние таблицы из VoxLibris;

- исходных файлов книг;
