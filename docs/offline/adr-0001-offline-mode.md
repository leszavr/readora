# ADR-0001: Офлайн-режим Readora как PWA-функционал

- Статус: принято
- Дата: 2026-11-24
- Связано: `AGENTS.md` §11, `docs/offline/plan.md`

## Контекст

Readora — личная веб-библиотека (FB2/EPUB/MOBI/CBZ/TXT/MD/HTML). Чтение полностью
серверозависимо: парсинг и рендер книг на сервере (`htmlContent` глав), прогресс,
закладки и заметки — через API. PWA-установка реализована (manifest + SW-заглушка),
но app shell не кэшируется, контент офлайн недоступен.

Пользователь читает с мобильных устройств; нужен офлайн-доступ к начатым книгам
и возможность загрузить локальные файлы книг в поездках.

Ограничения среды:

- сессии — cookie (`express-session`), все запросы `credentials: include`;
- Safari вытесняет IndexedDB неактивных PWA (~7 дней) — офлайн на iOS не гарантирован;
- исходного файла книги с клиента скачать нельзя (только админский эндпоинт);
- серверный прогресс — зрелая семантическая модель v2 (text-anchor), `currentPosition`
  хранится сервером как opaque-строка до 8000 символов, upsert идемпотентен.

## Решение

1. **Серверный ридер не меняется.** Существующий путь чтения (парсинг на сервере,
   рендер `htmlContent`) остаётся единственным для онлайн-чтения. Офлайн-ридер —
   отдельный клиентский путь, написанный с нуля.
2. **Клиентский рендер — foliate-js (MIT)**, vendored в
   `artifacts/readora/src/offline/vendor/foliate-js/` (npm-пакета нет).
   Форматы первого этапа: EPUB, FB2 (вкл. fb2.zip/fbz), CBZ, TXT, MD, HTML.
   MOBI отложено до отдельной потребности.
3. **Хранение — raw IndexedDB** (БД `readora-offline`), без обёрток (idb/Dexie/RxDB).
   Прецедент — `src/lib/analytics.ts`. App shell — Service Worker (precache),
   инструмент precache — отдельное решение на этапе 2 (см. план).
4. **Структурная изоляция**: весь офлайн-код во фронтенде в
   `artifacts/readora/src/offline/`; офлайн-логика не вмешивается в основной код
   ридера и библиотеки (точки интеграции — узкие хуки/адаптеры).
5. **Схема кэша**: книги с прогрессом чтения кэшируются автоматически (LRU по
   последнему открытию, без жёсткого лимита) + до 10 локально загруженных книг.
6. **Синхронизация**: две независимые очереди в IndexedDB.
   - Прогресс: офлайн-сохранения отправляются в `PUT /books/:id/progress`
     при появлении сети; конфликты — last-write-wins по timestamp.
   - Локальные книги: выгрузка через существующий `POST /books/upload`
     (job-модель без изменений сервера); после успешной выгрузки книги без
     прогресса удаляются из офлайн-хранилища.
7. **Позиция чтения офлайн-ридера** сериализуется в `currentPosition` как
   offline-вариант (version: 3) с text-anchor (цитата + контекст). Сервер
   хранит её opaque; кросс-ридерное восстановление (офлайн → серверный ридер
   и обратно) — через text-anchor, с fallback на главу/процент.
8. **Новый эндпоинт** `GET /api/books/:id/file`: приватный, `requireAuth`,
   проверка владельца, стрим исходного файла. Бинарный ответ — в OpenAPI
   не добавляется (прецедент: `/api/books/:id/cover`). Клиент кэширует блоб
   напрямую, без codegen.
9. **Безопасность**: офлайн-хранилище не шифруется (данные принадлежат
   пользователю устройства), но полностью очищается при logout/смене аккаунта
   (IndexedDB + SW-кэши).
10. **Разработка в ветке `feature/offline`**; мерж в `main` только после
    масштабного успешного локального тестирования, подтверждённого пользователем.
11. **Нативное мобильное приложение не планируется.** Возможная будущая опция —
    Capacitor-обёртка существующего фронтенда (отдельным решением).

## Рассмотренные альтернативы

- **epub.js** — только EPUB, тяжёлый, слабо развивается. Отклонён.
- **Readium** — тяжеловесный, издательская ориентация. Отклонён.
- **Кэшировать распарсенные главы (`htmlContent`) вместо исходников** —
  оставляет серверозависимый рендер, не даёт локальную загрузку файлов,
  дублирует половину ридера. Отклонено.
- **RxDB / Dexie Cloud / репликация-фреймворки** — тянут свою инфраструктуру
  и серверную часть; наша синхронизация — две простые очереди. Отклонено.
- **Нативное Android-приложение (Kotlin)** — второй продукт (своя авторизация,
  API-клиент, рендерер без FB2-поддержки в Readium Kotlin), поддержка удваивается.
  Отклонено; Capacitor — опция на будущее.
- **Единый рендер-путь (онлайн тоже через foliate-js)** — меняет стабильный
  серверный ридер, конфликтует с требованием «серверный ридер не трогаем».
  Отклонено.

## Последствия

- Появляется второй рендер-путь книг → нужен адаптер позиций (этап 3) и
  двойное тестирование форматов; это принятая цена изоляции серверного ридера.
- iOS: офлайн-кэш может быть вытеснен системой при долгом неиспользовании PWA —
  честно документируем как ограничение, не обходим.
- Новых npm-зависимостей на этапе 1–3 нет (foliate-js vendored, IndexedDB raw).
  Единственный кандидат — инструмент precache SW на этапе 2 (vite-plugin-pwa),
  согласуется с пользователем отдельно.
- `GET /api/books/:id/file` расширяет приватную поверхность API: эндпоинт
  обязан проверять владельца так же строго, как `/cover` и `/chapters`.
