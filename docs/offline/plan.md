# План реализации офлайн-режима Readora (PWA)

Статус: в работе. Ветка: `feature/offline`. Мерж в `main` — только после масштабного
успешного локального тестирования, подтверждённого пользователем (см. `AGENTS.md` §11
и ADR-0001).

Правило этапов: каждый этап завершается рабочим, проверенным состоянием (typecheck +
unit-тесты core где применимы). Не начинаем следующий этап с незакрытым предыдущим.

## Этап 0 — Ветка и документация

- [x] Ветка `feature/offline` от `main`
- [x] ADR-0001 «Офлайн-режим PWA» (`docs/offline/adr-0001-offline-mode.md`)
- [x] Этот план с чекбоксами
- [x] Зафиксированы решения в `AGENTS.md` §11

## Этап 1 — Хранение и кэш книг (офлайн-фундамент)

- [x] IndexedDB-модуль `artifacts/readora/src/offline/db.ts`: БД `readora-offline`,
      object stores: `books` (файл-блоб + метаданные + lastAccessAt), `pending`
      (очередь синхронизации), `meta` (счётчики, версия схемы)
- [x] Серверный эндпоинт `GET /api/books/:id/file` (`requireAuth`, проверка владельца,
      стрим из `storageKey` или внешнего облака — по образцу админского download,
      но без `requireAdmin`). Бинарный, как `/cover` — в OpenAPI не добавляется
- [x] Cache manager `src/offline/book-cache.ts`: загрузка файла книги + обложки +
      метаданных в IndexedDB, обновление `lastAccessAt`, LRU-вытеснение книг с прогрессом
- [x] Триггер кэширования: при открытии книги в онлайне — фоновое кэширование
- [x] Инвалидация: книга удалена/заменена на сервере → удаление из кэша
- [x] UI: индикатор «доступна офлайн» на карточке книги в библиотеке
- [x] Unit-тесты LRU/инвалидации (node --test, как reader/core)

## Этап 2 — App shell офлайн (Service Worker)

- [x] Решение по инструменту: `vite-plugin-pwa` (ADR-0002) — build-time генерация
      `sw.js`; на проде раздаётся Express как статика, деплой не меняется,
      devDependency только фронтенда
- [x] Precache Vite-бандла (hashed assets) + fallback-навигации (SPA-роуты →
      `index.html`; SSR-страницы и `/api/*` исключены)
- [x] Стратегия обновления SW (autoUpdate: skipWaiting + cleanupOutdatedCaches,
      поверх существующей регистрации в `main.tsx`)
- [ ] Проверка: установка PWA, airplane-mode, открытие приложения офлайн
      (прогон в браузере — пользователь)

## Этап 3 — Офлайн-ридер (foliate-js)

- [ ] Vendor foliate-js (MIT) в `src/offline/vendor/foliate-js/` (пакета в npm нет)
- [ ] Рендер из blob: EPUB, FB2 (вкл. fb2.zip/fbz), CBZ, TXT, MD, HTML. MOBI — отложено
- [ ] Вписать рендер в существующий UI-стиль ридера (тема, шрифты, пагинация)
- [ ] Адаптер прогресса: позиция foliate-js → `currentPosition` (offline-вариант,
      версия 3, opaque для сервера) + text-anchor для восстановления позиции
      в серверном ридере и наоборот
- [ ] Выбор рендер-пути: офлайн-ридер только когда нет сети/кэш актуален;
      серверный ридер не меняется
- [ ] Unit-тесты адаптера позиций

## Этап 4 — Локальные книги (лимит 10)

- [ ] Выбор локальных файлов (file picker) → сохранение в IndexedDB
- [ ] Извлечение метаданных и обложки из файла через foliate-js
- [ ] Секция «Локальные» в библиотеке, состояние «ждёт выгрузки»
- [ ] Лимит 10 локальных книг + внятное уведомление при превышении

## Этап 5 — Синхронизация

- [ ] Очередь прогресса: офлайн-сохранения → `PUT /books/:id/progress`,
      last-write-wins по timestamp (серверный upsert уже идемпотентен)
- [ ] Очередь выгрузки локальных книг: `POST /books/upload` + поллинг job
      (существующий контракт, без изменений сервера)
- [ ] Локальные книги без прогресса после успешной выгрузки удаляются из офлайн-хранилища
- [ ] Flush при появлении сети/запуске приложения, ретраи с backoff
- [ ] UI: статус синхронизации (ожидает/синхронизировано/ошибка)
- [ ] Unit-тесты очереди и LWW-разрешения конфликтов

## Этап 6 — Безопасность и очистка
